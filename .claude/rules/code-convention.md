# Kotlin & Spring Convention

- Kotlin 공식 스타일에 맞춰 공백 4칸으로 들여쓰고 탭을 사용하지 않습니다.
- 논리적으로 구분되는 선언과 처리 단계 사이에는 빈 줄을 둡니다.
- 이름만으로 역할이 드러나는 클래스, 메서드, 변수명을 사용합니다.
- 불필요한 추상화, 과도한 메서드 분리, 범위를 벗어난 구현을 피합니다.
- 변경되지 않는 값은 `val`을 사용하고 `!!` 사용을 피합니다.
- Scope Function을 중첩하거나 가독성을 해칠 정도로 사용하지 않습니다.

## 계층과 API

- Controller는 요청 검증과 응답 변환을 담당합니다.
- 비즈니스 로직은 Service 또는 도메인 객체에 둡니다.
- Repository에는 데이터 접근 책임만 둡니다.
- Entity를 API 요청이나 응답으로 직접 사용하지 않습니다.
- API 성공 응답은 `ApiResponse`, 비즈니스 오류는 `BusinessException`과 `ErrorCode`를 사용합니다.

## JPA와 트랜잭션

- JPA Entity에 `data class`를 사용하지 않습니다.
- public setter 대신 의미가 드러나는 상태 변경 메서드를 사용합니다.
- 쓰기 작업에는 적절한 트랜잭션 경계를 설정합니다.
- 조회 작업은 필요한 경우 `@Transactional(readOnly = true)`를 사용합니다.
- N+1, 반복문 내부 쿼리, 지연 로딩 범위 이탈을 확인합니다.

## 테스트

- 비즈니스 규칙, 예외 상황, 경계값을 우선 검증합니다.
- 구현을 그대로 반복하거나 가치가 낮은 테스트는 만들지 않습니다.
