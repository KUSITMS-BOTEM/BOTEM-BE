# Git Commit 커맨드

## 사용법

```text
/commit
```

## 동작 순서

1. `git status`, `git diff`, `git diff --cached`를 실행해 변경 사항 전체를 파악한다.
2. 변경된 파일과 내용을 분석해 커밋 타입과 한글 메시지를 결정한다.
3. 스테이징되지 않은 파일이 있으면 어떤 파일을 포함할지 사용자에게 확인한다.
4. 관련 없는 변경 사항이 섞여 있으면 분리 커밋을 제안한다.
5. 아래 형식으로 커밋 메시지를 제안하고 확인을 받은 뒤 커밋한다.
6. 커밋 완료 후 커밋 해시와 메시지를 출력한다.

## 커밋 메시지 형식

```text
<type>: <한글 메시지>
```

### 타입 선택 기준

| 타입 | 사용 시점 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `hotfix` | 운영 환경 긴급 오류 수정 |
| `refactor` | 기능 변경 없는 코드 개선 |
| `docs` | 문서 및 주석 변경 |
| `test` | 테스트 코드 추가 및 수정 |
| `chore` | 기타 설정 및 유지보수 |
| `build` | 빌드 및 의존성 변경 |
| `ci` | CI/CD 설정 및 워크플로 변경 |
| `perf` | 성능 개선 |

### 한글 메시지 작성 규칙

- 변경 목적과 해결한 문제를 명확하게 작성한다.
- 명사형 종결을 사용한다. 예: `추가`, `수정`, `제거`, `개선`
- 50자 이내로 간결하게 작성한다.
- 제목 끝에 마침표를 사용하지 않는다.

예시:

```text
feat: 펀딩 개설 API 추가
feat: 펀딩 메시지 작성 기능 추가
fix: 펀딩 참여 금액 검증 오류 수정
refactor: 펀딩 조회 로직 개선
build: 검증 의존성 추가
ci: GitHub Actions 테스트 워크플로 추가
```

## 주의사항

- `.env`, 시크릿, 비밀번호, 토큰이 포함된 파일은 커밋하지 않는다.
- `git add .`, `git add -A`로 모든 파일을 일괄 스테이징하지 않는다.
- 새로 생성된 파일도 확인 대상에 포함한다.
- 이미 스테이징된 파일도 커밋 전에 검토한다.
- 관련 없는 변경 사항이 섞여 있으면 분리 커밋을 제안한다.
- 사용자 확인 없이 커밋하거나 Push하지 않는다.
- `--amend`, `--no-verify` 옵션은 사용자 확인 없이 사용하지 않는다.
