# 브랜치 생성 커맨드

## 사용법

```text
/branch <이슈번호> <설명>
```

예시: `/branch 156 funding-create`

## 동작 순서

### 1. 인자 파싱

- `$ARGUMENTS`에서 이슈번호와 설명을 파싱한다.
- 이슈번호가 양의 정수인지 확인한다.
- 설명은 영문 소문자, 숫자, 하이픈으로 구성한다.
- 필수 인자가 누락되면 사용자에게 입력을 요청한다.

### 2. 브랜치 타입 선택

사용자에게 브랜치 타입을 선택하도록 요청한다.

| 타입 | 사용 시점 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `hotfix` | 운영 환경 긴급 오류 수정 |
| `refactor` | 기능 변경 없는 코드 개선 |
| `docs` | 문서 및 주석 변경 |
| `test` | 테스트 코드 추가 및 수정 |
| `chore` | 빌드, 설정 및 기타 변경 |

### 3. 작업 환경 확인

- `git status --short`로 커밋되지 않은 변경 사항을 확인한다.
- 변경 사항이 존재하면 사용자에게 알리고 진행 여부를 확인한다.
- 기존 변경 사항을 임의로 Commit, Stash, Reset하지 않는다.
- 동일한 이름의 로컬 및 원격 브랜치가 존재하는지 확인한다.
- 브랜치가 이미 존재한다면 새로 생성하지 않고 사용자에게 알린다.

### 4. 브랜치명 생성 및 확인

```text
<type>/#<이슈번호>-<설명>
```

예시:

```text
feat/#156-funding-create
feat/#157-funding-message
fix/#158-funding-participation-amount
refactor/#160-funding-service
```

생성할 브랜치명과 분기 기준 브랜치를 사용자에게 보여주고 확인을 요청한다.

### 5. 브랜치 생성

일반 브랜치는 `develop`에서 분기한다.

```bash
git fetch origin develop
git checkout -b <브랜치명> origin/develop
git push -u origin <브랜치명>
```

`hotfix`는 `main`에서 분기한다.

```bash
git fetch origin main
git checkout -b <브랜치명> origin/main
git push -u origin <브랜치명>
```

- 각 명령의 성공 여부를 확인한 뒤 다음 명령을 실행한다.
- 명령 실행에 실패하면 후속 명령을 중단하고 오류를 보고한다.
- 실패 시 브랜치를 임의로 삭제하거나 강제 Push하지 않는다.

### 6. 완료 안내

- 생성된 브랜치명
- 분기 기준 브랜치
- 원격 브랜치 생성 여부
- 현재 체크아웃된 브랜치

## 주의사항

- `main`, `develop` 브랜치에서 직접 작업하지 않는다.
- 기존 변경 사항을 임의로 삭제하거나 덮어쓰지 않는다.
- 사용자 확인 없이 브랜치를 생성하거나 Push하지 않는다.
- 브랜치 생성 후 다른 브랜치로 임의 전환하지 않는다.
- 브랜치 생성에 실패하면 원인을 안내하고 작업을 중단한다.
