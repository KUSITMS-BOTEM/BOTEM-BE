# 핵심 유저 플로우 — 보탬

> 핵심 루프: **등록 → 공유 → 보태기 → 달성 → 수령 → (참여자의 개설 전환)**
> 마지막 단계가 다시 첫 단계로 이어지는 것이 성장 루프의 핵심.

## 0. 전체 흐름

```
[개설자]                        [참여자]
상품 등록 ──▶ 링크 공유 ──▶ 링크 클릭 (가입 없이)
   │                              │
   │                         금액 선택 + 메시지 작성
   │                              │
   │                           결제
   ▼                              │
진행률 확인 ◀──── 진행률 갱신 ◀───┘
   │
목표 달성 (또는 기한 만료)
   │
   ├─ 달성 ──▶ 상품 수령 + 참여자 메시지 확인 ──▶ 감사 인사 발송
   │                                                │
   └─ 미달성 ─▶ [D-1 정책에 따름]                    ▼
                                        참여자에게 완성 알림
                                        "나도 만들어볼까?" ← 전환 포인트
```

## 1. 펀딩 개설 (받는 사람)

| 단계 | 화면/행동 | 핵심 설계 포인트 |
|---|---|---|
| 1-1 | 상품 등록 (링크 붙여넣기 or 카탈로그 선택) | 링크 파싱으로 이미지·가격 자동 추출. [D-2](05-정책결정서.md) |
| 1-2 | 사연/계기 작성 (생일, 취업 등) | "사줘"가 아니라 "축하받는" 프레임으로 체면 부담 완화 (H1 대응) |
| 1-3 | 기한·공개 범위 설정 | 기본값을 잘 정해 설정 부담 최소화 |
| 1-4 | 공유 링크 생성 → 카톡 공유 | 카톡 미리보기(OG 태그)가 첫인상 — 진행률·상품 이미지 노출 |

## 2. 보태기 (참여자) — 가장 마찰이 적어야 하는 구간

| 단계 | 화면/행동 | 핵심 설계 포인트 |
|---|---|---|
| 2-1 | 링크 클릭 → 펀딩 페이지 | **가입·설치 없이 열람** (H2의 전제조건) |
| 2-2 | 금액 선택 | 추천 금액 버튼(5천/1만/2만) + 직접 입력. 남은 금액 표시 |
| 2-3 | 메시지 작성 | 송금과의 차별점 — 축하 메시지가 선물의 일부 |
| 2-4 | 결제 | 카카오페이/토스/카드. 3탭 이내 완료 목표 |
| 2-5 | 완료 화면 | 진행률 애니메이션 + "내 보탬이 N%를 채웠어요" |

## 3. 달성 / 수령

| 단계 | 화면/행동 | 핵심 설계 포인트 |
|---|---|---|
| 3-1 | 달성 알림 (개설자 + 전체 참여자) | 참여자에게도 "함께 완성했다" 순간 공유 — 전환 포인트 |
| 3-2 | 상품 수령 절차 | [D-2 결정](05-정책결정서.md)에 따름 (대리구매 vs 기프트카드) |
| 3-3 | 참여자 메시지 모아보기 | 롤링페이퍼 경험. 감정적 클라이맥스 |
| 3-4 | 감사 인사 발송 | 개설자→참여자. 루프 종결 + 관계 강화 |

## 4. 미달성 플로우 (⚠️ 달성 플로우보다 먼저 설계할 것)

- 기한 만료 시점 처리: [D-1 정책](05-정책결정서.md) 확정 후 상세화
- 원칙: 미달성이어도 참여자의 마음(메시지)은 반드시 전달되는 경험 설계
