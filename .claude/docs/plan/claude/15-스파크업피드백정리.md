## 디벨롭 판단

### 핵심 진단

1~5번(총 32회 언급)은 사실상 **한 가지 뿌리**에서 나온다: MVP를 "개설자 계좌 직송금(B)"으로 잡은 것.
B 때문에 입금 확인이 안 되고, 미달성 처리가 성립하지 않고, 모아줘와 같아 보이고, 서프라이즈 모드에서 총무가 부활하고, 쿠팡 수익도 누수된다.
내부적으로는 P1~P3로 이미 알던 문제지만, 외부 31명이 거의 똑같이 지적했다는 건 **"알고 있다"가 기획서에 답으로 드러나지 않았다**는 뜻이다. 문제를 아는 것과 답을 적는 것은 다르다.

### 결정 1. B를 유지하되 "B는 검증 장치, 차별점은 돈 바깥"이라고 못 박기 (추천)

개발 기간(10/24~11/26)이 고정이라 지금 A(PG 수납)로 갈아타는 건 무리다. #5, 24의 PG 심사 탈락 경험담도 있어 A는 사전 확인 없이 일정에 넣으면 위험하다.

- 진행률: #21 흐름을 그대로 채택 — `참여 신청(대기) → 개설자 '받았어요' 체크 → 반영`. 게이지는 확정분만, 대기분은 흐리게. 운영자 확인 문구는 기획서에서 삭제
- 차별점은 돈이 아니라 경험 레이어로 재정의: 메시지만 참여(#13), 감사 회신(#1), 역할 뱃지, 당일 일괄 공개. 이 셋이 모아줘에 없는 것이고 카카오 송금으로 대체 안 되는 것
- 카피 수정: "총무도 정산도 없이" → "총무의 **일**(확인·독촉·정산)이 사라진다". 총무라는 사람은 남아도 노동은 없앤다는 쪽이 정직하고 서프라이즈 모드와도 충돌하지 않는다

### 결정 2. D-1을 지금 확정 — "모인 만큼 전달" + 연출

- B에서는 '실패'가 존재할 수 없으므로 목표는 게이지일 뿐, 기한에 모인 만큼 전달
- #31 아이디어 채택: 목표 미달이면 "OO에게 친구들이 보낸 축하금 봉투" 연출 + 모인 금액에 맞는 대체 상품 추천(#14 가격 변동 문제도 같은 화면에서 해소)
- 미달 시 개설자 선택지: ① 기한 연장 ② 차액 본인 부담 후 원래 상품 ③ 대체 상품 ④ 축하금으로 수령

### 결정 3. 스코프 축소 — 3층 구조 재검토

#8, 17, 19의 지적과 5주 일정을 같이 보면, MVP는 **3층(펀딩) + 최소 위시 프로필**에 집중하고 1층 취향 테스트는 런칭 후 12월 시즌 캠페인용으로 미루는 게 맞다고 본다.
"재미 vs 정확한 선물"(#17)에 대한 답은: **핵심은 '원하는 선물을 정확히 받기', 재미는 참여 전환을 높이는 수단**. 재미 요소마다 "어떤 지표를 올리는가"를 붙여 화면 장식과 구분(#19).

### 결정 4. 서프라이즈 모드 정의 정리

- 두 경로를 명확히 분리: ① 본인 개설(정방향, 돈 → 본인) ② 친구 개설(서프라이즈, 돈 → 개설한 친구)
- "D-30 자동 전환"은 ①에만 해당, 본인에게 "펀딩으로 열까요?" 알림을 보내는 방식으로 변경 (#27 혼란 해소)
- 서프라이즈는 MVP에서 초대 링크만 있는 축소판, A 단계(플랫폼이 기프티콘 발송)에서 완성판 — 그때 총무 문제가 구조적으로 사라짐

### 결정 5. "사줘와 뭐가 다른가"(#30)에 대한 답을 기획서에 명시

답의 재료는 이미 있다:
- 홍보 주체를 바꾼다: 서프라이즈(친구가 연다), 참여자용 자랑 카드(참여자가 퍼뜨린다)
- 홍보 시점을 바꾼다: 위시 프로필을 평소에 링크인바이오처럼 걸어두면 생일 직전의 "사줘"가 아니다
- 일방성을 없앤다: 개설자 공약, 감사 회신(#1)
단, 이건 주장일 뿐이라 H1 검증 결과(설문·인터뷰)로 뒷받침해야 한다. #9 지적대로 해외 사례는 근거가 약하니 국내 데이터를 앞에 세울 것.

### 결정 6. A 단계 준비는 병렬로 (개발 기간 중 리서치 트랙)

- PG 2곳(토스페이먼츠, 포트원)에 "참여자가 기프티콘 조각을 구매하는 통신판매 구조"로 사전 문의 → 심사 가능 여부 확인 (#5, 24)
- 테스트 모드로 결제·부분취소 흐름 프로토타이핑 (#25)
- 기프티쇼 비즈 API 연동 설계를 미리 (#10)
- 앱인토스 가능성 확인 (#19)
