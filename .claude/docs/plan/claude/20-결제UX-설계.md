# 20. 결제 구조 심화 리서치 + 결제 UI 설계 (2026-10-12)

> [19-결제구조-선불규제](19-결제구조-선불규제.md)의 3단계 구조(B → A → 포인트)를 화면으로 옮기기 위한 문서.
> 관련: [05-정책결정서](../05-정책결정서.md) D-1·D-4·D-5, [06-유저플로우](../06-유저플로우.md), [07-MVP요구사항](../07-MVP요구사항.md)
> ⚠️ 규제·약관 관련 내용은 공개 자료 기준이며 법률 자문이 아님.

**한 줄 요약**: 참여자 화면은 단계가 바뀌어도 똑같이 두고(금액 → 메시지 → 보탬하기), **'돈을 보내는 한 칸'만 갈아 끼운다.** 1단계는 토스 아이디 금액 링크 + 계좌 복사, 2단계는 PG 결제위젯. 진행률은 '확정'과 '대기'를 나눠 보여 준다.

## 1. 리서치에서 새로 확인한 것

### 1-1. 송금 수단별 실제 동작

| 수단 | 금액 미리 채우기 | 받는 사람 실명·계좌 노출 | 토스 미가입자 | 비고 |
|---|---|---|---|---|
| **토스 아이디 링크** `toss.me/아이디/금액` | ✅ 링크 끝에 금액을 붙이면 고정 | 노출 안 됨 | 링크 페이지의 가상계좌로 송금 가능 | 베타 서비스(예고 없이 변경 가능). **보낸 송금은 취소·반환 불가.** 토스 앱으로 보내면 보낸 사람 실명도 숨겨짐 → 개설자가 누가 보냈는지 매칭하기 어려움 |
| 토스 앱 스킴 `supertoss://send?...` | ✅ 은행·계좌·금액 | 계좌 노출 | 앱 필수 | 비공식 스킴. PC에서 동작 안 함. **사용하지 않는다** (약관·안정성) |
| 카카오페이 송금 | ❌ 외부에서 계좌·금액 미리 채우는 링크·API 없음 (카카오페이 개발자 포럼, 2024-01 답변) | — | — | 카카오페이 사용자는 '계좌 복사'로 처리 |
| 계좌번호 복사 | ❌ (참여자가 직접 입력) | 계좌 노출 | 모든 은행 앱 | 가장 범용적인 폴백 |

→ **1단계 기본 = 토스 아이디 금액 링크, 폴백 = 계좌 복사.**

### 1-2. 경쟁·유사 서비스

| 서비스 | 구조 | 배울 점 |
|---|---|---|
| 모아줘 | 선물 + 계좌번호 입력 → 링크 공유 → 친구가 계좌로 직접 송금, "수수료 없이 계좌로 바로" | B 구조로 생존 중. 미달성 처리·수익 모델은 공개 안 됨 |
| 프레제뉴 | 함께 결제 → 달성 시 배송 | 2026-01 이후 서비스 종료, 신규 가입 중단. 실물 대리구매(A′)의 무게 |
| PayIt2 (해외) | 링크 하나, 가입 불필요, 추천 금액, **개인 금액은 개설자만**, 진행률 바, 미참여자 리마인드 | D-5 기본값 근거 |
| Thankbox 등 (해외) | 돈 + 단체 카드(메시지)를 한 번에 | "송금이 아니라 선물"이 되는 핵심 = 메시지 |
| Cash App Pools (2025-07) | 목표 금액 + 참여자 장부 + 링크로 비회원 참여 | 대형 핀테크도 같은 패턴으로 수렴 |

## 2. 설계 원칙

1. **참여자 흐름은 하나.** 금액 → 메시지 → 보탬하기 → 완료. 단계가 바뀌어도 이 순서·화면은 그대로.
2. **"돈 보내는 칸"만 어댑터로 교체.** 1단계 = 송금 링크 / 2단계 = PG 결제위젯 / 3단계 = 포인트 차감.
3. **약속 먼저, 송금 나중 (pledge-first).** 메시지·금액을 먼저 저장하고 송금 앱으로 보낸다. 앱 전환 후 안 돌아와도 기록이 남는다.
4. **진행률은 확정분만 '채움'.** 대기분은 옅은 색으로 따로. 신뢰(P2)와 정직함.
5. **개인 금액은 개설자만 본다** (D-5 ③ 권장). 다른 참여자에게는 이름·메시지·인원수만.
6. **'실패'라는 말이 없다** (1단계 D-1: 기한이 되면 모인 만큼 전달).
7. **보탬은 돈을 보관하지 않는다는 걸 화면에 적는다.** 신뢰 + 규제 포지션 명확화.
8. 단위는 처음부터 **"○만 보탬"** ([18-브랜딩](18-브랜딩-디자인무드.md)).

## 3. 1단계(B) 화면 설계 — 12/5 MVP

### 3-1. 참여자 흐름

| # | 화면 | 내용 | 설계 포인트 |
|---|---|---|---|
| P1 | 펀딩 페이지 | 상품 이미지, 사연, 진행률(확정+대기), 남은 금액, 참여 인원, 메시지 미리보기 | 가입 없이 열림. 개인 금액 비노출 |
| P2 | 금액 선택 | `5천 보탬` `1만 보탬` `2만 보탬` `남은 만큼` + 직접 입력 | '남은 만큼' 버튼 = 마지막 사람 유도 |
| P3 | 이름 + 메시지 | 닉네임(필수), 축하 메시지(선택), 사진/스티커(Should) | 저장 시점 = 'pledge 생성(대기)' |
| P4 | 보내는 방법 | **[토스로 보내기]** (금액 자동 입력, 추천 뱃지) / **[계좌번호 복사]** (다른 은행·카카오페이) | 상단 안내: "송금은 토스·은행 앱에서 진행돼요. 보탬은 돈을 보관하지 않아요." / "보낸 송금은 취소가 어려워요" |
| P5 | 돌아왔을 때 | "○○님께 1만 보탬 보내셨나요?" **[보냈어요]** / [아직이에요] | 앱 복귀(visibilitychange) 감지해서 자동으로 띄움. [아직이에요] → 대기 유지 + 다시 보내기 버튼 |
| P6 | 완료 | "1만 보탬 했어요" + 진행률 애니메이션(대기 색으로 채워짐) + "○○님이 확인하면 반영돼요" + 공유 버튼 | 참여자 → 개설 전환 포인트("나도 만들기") |

PC 접속: `toss.me` 링크는 웹에서 열리고 가상계좌·QR 안내가 나오므로 별도 처리 불필요. 계좌 복사는 그대로 동작.

### 3-2. 개설자 흐름

| # | 화면 | 내용 | 설계 포인트 |
|---|---|---|---|
| O1 | 받는 방법 등록 | **토스 아이디 입력 (추천)** 또는 계좌(은행·번호·예금주) | 토스 아이디 장점: 계좌·실명 숨김. 입력 즉시 `toss.me/아이디` 미리보기 열기 버튼으로 본인 확인 |
| O2 | 대시보드 | 진행률(확정/대기), **확인 대기 목록** (이름·금액·시각) → **[받았어요]** / [못 받았어요], 상단에 [모두 받았어요] | 토스 앱 송금은 보낸 사람 실명이 안 보일 수 있으므로 **금액 + 시각**으로 맞추게 정렬. 대기가 쌓이면 푸시 |
| O3 | 기한 마감 | "모인 15만 보탬으로 선물을 사 볼까요?" + 상품 구매 버튼(쿠팡 파트너스) | 버튼 근처에 대가성 문구 필수: "쿠팡 파트너스 활동의 일환으로 수수료를 제공받습니다" |
| O4 | 선물 도착 인증 | 사진 업로드 → 참여자에게 완성 알림 + 롤링페이퍼 공개 | P6(수익 누수) 대응 + 감사 카드 |

### 3-3. 상태(원장) 설계 — 개발팀 전달용

| 필드 | 값 |
|---|---|
| pledge_id, funding_id | — |
| nickname, message | 참여자 입력 |
| amount | 정수(원). UI 표기만 "보탬" |
| status | `pending`(보냈어요) → `confirmed`(받았어요) / `cancelled`(못 받았어요·취소) |
| method | `toss_link` / `account_copy` → 2단계 `pg_card` / `pg_easypay` → 3단계 `point` |
| created_at, confirmed_at | 분기별 집계 가능하게 |
| pg_payment_key | 2단계용(지금은 null) |

진행률 = `sum(confirmed)` 진하게 + `sum(pending)` 옅게. 마감 시 `pending`이 남아 있으면 개설자에게 정리 요청.

### 3-4. 1단계 예외 케이스

| 케이스 | 처리 |
|---|---|
| '보냈어요' 눌렀는데 실제로 안 보냄 | 개설자 [못 받았어요] → cancelled. 진행률에서 빠짐. 참여자 비회원이라 알림 불가 → 페이지 재방문 시 표시 |
| 송금했는데 '보냈어요'를 안 누름 | 개설자 대시보드 [직접 추가] (이름·금액 입력) |
| 목표 초과 | "목표 달성! 계속 보탤 수 있어요" — 막지 않음 |
| 기한 내 미달성 | '실패' 없음 → "모인 ○만 보탬을 전달했어요" 완성 화면 |
| 토스 링크 오류(베타 변경 등) | 계좌 복사로 자동 폴백. 개설 시 계좌도 함께 받아 두는 것 권장 |

## 4. 2단계(A) 화면 — 바뀌는 것만

| 항목 | 1단계 | 2단계 |
|---|---|---|
| P4 보내는 방법 | 토스 링크 / 계좌 복사 | **PG 결제위젯** (카드·간편결제만. 가상계좌·휴대폰 제외) |
| 금액 표시 | "1만 보탬" | "1만 보탬 (수수료 포함)" + 펼치면 상품가/수수료 내역 (D-4 gross-up 투명 고지) |
| P5 확인 | 참여자 '보냈어요' + 개설자 '받았어요' | **결제 승인 = 즉시 confirmed** (개설자 확인 단계 삭제) |
| 미달성 | 모인 만큼 전달 | D-1 결정: 부분취소 환불 vs 모인 만큼 금액권 |
| O3 마감 | 쿠팡 링크 | 달성 시 기프티콘 자동 발송 |
| 하단 정보 | 사업자 정보 | + 통신판매업 신고번호, 환불정책 |

→ 참여자 화면 구조는 그대로, P4·P5만 교체. 1단계를 이 구조로 만들면 2단계 전환 비용이 작다.

## 5. 3단계(포인트) — 지금 UI에 남겨 둘 것

- 금액 단위 "보탬"을 버튼·완료·알림 모두 통일 (나중에 잔액 "12,000 보탬"으로 자연스럽게 연결)
- `method` 필드에 `point` 자리만 확보
- 무상 리워드 포인트(C-0)부터 시작한다면 "참여 보상 500 보탬" 같은 UI만 추가
