# 커피챗 즉답 카드 — 보탬 (2026-10-03)

기준: 스파크업 발표 장표(Botem.pdf) + 노션 spark-up / 커피챗 질의응답 준비. 장표와 노션이 다르면 장표(최신)를 따름.

## 0. 30초 소개
갖고 싶은 선물을 친구들이 조금씩 보태서 완성해 주는 퍼스널 크라우드펀딩이에요. 총무가 하던 여섯 단계(단톡방-계좌-입금확인-독촉-정산-대신구매)를 링크 하나로 줄이고, 송금 도구가 아니라 '선물이 완성되는 경험'을 만드는 게 목표예요.

## 1. 숫자 치트
- e쿠폰 거래액 2.9조(2019) → 10.1조(2023), 4년 만에 약 3.4배
- 카카오톡 선물하기 거래액 3.8조(2023) = SAM
- 카톡 선물하기 이용 경험률 20대 79.7% / 30대 74.8% / 40대 70.4%
- 자기구매 거래액 +39% (2026년 2분기, 전년 동기 대비)
- 수익: 쿠팡 파트너스 1~3% → 30만 원 상품 기준 펀딩당 3천~9천 원 (전자기기는 약 1%)
- 검증 기준: 링크 받은 친구 50% 이상 실제 참여 / 위시 등록 요청 5명 중 3명 이상 등록
- 밋업 5주: 펀딩 페이지 1개 완성 + 취향 테스트·결제 연동 테스트
- 핵심 지표: 월간 완성 펀딩 수 / 참여자→개설자 전환율

## 2. 공통
**모아줘랑 뭐가 달라요?**
돈 흐름은 비슷한데 두 가지가 달라요. ① 진행률 신뢰: 모아줘는 참여만 눌러도 오르지만, 보탬은 받는 사람이 '받았어요'를 눌러야 확정돼요. ② 선물 경험: 현금 전달이 아니라 제휴 링크 구매 → '선물 도착' 인증까지 이어져요.

**카카오가 '함께 선물하기' 내면 끝 아니에요?**
카카오는 자기 회원·자기 상품 안에서만 움직여요. 보탬은 비회원 참여, 어느 쇼핑몰 상품이든 등록, 놀이형 펀딩 페이지처럼 카카오가 안 하는 영역에 집중해요. 그리고 카톡은 사람들이 먼저 모여 협의해야 시작되지만, 보탬은 위시가 먼저 있고 서로 모르는 친구들도 각자 보탤 수 있어요.

**목표 못 채우면요?**
실패로 안 봐요. 기한이 되면 모인 만큼 전달하고, 맞는 대체 상품을 추천하거나 기간을 연장할 수 있어요.

**받은 돈을 다른 데 쓰면요?**
제휴 링크로 사면 '선물 도착' 인증이 되고, 참여자 모두에게 완성 알림이 가요. 인증한 사람에게 감사 카드 같은 보상을 줘서 링크 구매를 유도해요.

**"사줘"를 본인이 올리는 건 똑같지 않아요?**
그래서 사람이 아니라 시스템이 말하게 해요. 위시는 생일 직전이 아니라 평소 프로필에 걸어두고, 친구가 대신 여는 서프라이즈 모드, 남은 금액을 대신 조르는 밈 카피를 둬요. 가장 큰 가설(H1)이라 검증 중이고, 안 되면 서프라이즈 모드를 기본값으로 바꿔요.

**왜 결제 안 붙이고 송금으로 해요?**
돈을 직접 받아 보관하는 순간 PG 계약·규제가 붙고, 비슷하게 무겁게 간 프레제뉴는 문을 닫았어요. 운영은 송금으로 가볍게, 결제 시스템은 테스트 모드로 끝까지 만들어 두고 거래 실적이 쌓이면 켜요.

**수익은요?**
유저는 0원이에요. 친구 선물에서 떼지 않고, 커머스 쪽 제휴 수수료(1~3%)로 받아요. 작게 시작하지만 시장은 이미 10조예요.

**큐시즘 끝나도 해요?**
네, 전시회 전에 실배포해서 실제 유저를 모으고 그 뒤에도 계속 가는 게 목표예요.

**유저 리서치 결과 나왔어요?**
설문·인터뷰·실제 친구 생일 운영 테스트로 진행 중이에요. 통과 기준은 링크 받은 친구 절반 이상 참여, 위시 요청 5명 중 3명 이상 등록이에요.

## 3. 디자인
**디자이너 범위는?**
펀딩 페이지 UI와 진행률 인터랙션, 인스타로 퍼지는 공유·자랑 카드, 이걸 묶는 디자인 시스템이에요. 서비스 이름·브랜드부터 같이 정하고, 콘텐츠 마케팅까지 함께하면 좋겠어요.

**진행률 '조각' 형태 정해졌어요?**
방향만 있어요. 숫자보다 '남은 조각'이 직관적이어야 하고, 내가 채운 조각이 보여야 해요. 퍼즐·케이크·선물상자 같은 후보를 시안으로 같이 비교하고 싶어요.

**대기/확정은 어떻게 보여요?**
확정분만 게이지에 채우고 대기분은 흐리게요. 대기가 '불안'이 아니라 '곧 채워짐'으로 느껴지게 하는 게 디자인 과제예요.

**금액 숨기면 참여자는 뭘로 구분돼요?**
'첫 번째 보탬', '마지막 보탬' 같은 역할 뱃지로요. 돈 없이 메시지만으로도 참여할 수 있어요.

**가장 어려운 화면은?**
미달성 화면이요. "친구들이 여기까지 같이 모았다"로 느껴지게, 체면 안 상하는 감정 설계가 필요해서 디자이너 의견을 제일 듣고 싶어요.

**공유 카드는 몇 종?**
최소 두 개요. 개설자용 "지유 위시, 아직 0% — 조금씩 보태줘"와 참여자용 "세 번째로 보탬" 자랑 카드. 서버가 이름·진행률을 넣어 자동 생성하니, 이름 길이·0%/100% 같은 엣지 케이스를 고려한 템플릿 설계가 돼요.

**롤링페이퍼 당일 공개는?**
메시지가 생일 당일 한 번에 열리고, 받는 사람은 감사 인사와 인증샷으로 답해요. 공개 순간 연출부터 감사 회신까지 한 흐름으로 설계해요.

## 4. 프론트엔드
**웹이에요 앱이에요?**
모바일 웹이요. 앱 설치 없이 링크로 참여하는 게 핵심 조건이에요.

**비회원 3탭 흐름은?**
링크 진입 → 금액 선택 + 축하 메시지 → 송금 후 '보냈어요'. 가입·로그인 없이 끝나요.

**송금 완료를 프론트가 알 수 있어요?**
없어요. 그래서 '보냈어요' → 대기 → 받는 사람 확인 → 확정 구조예요. 송금 앱 갔다 돌아올 때 이탈을 줄이는 게 프론트 핵심 과제예요.

**진행률 애니메이션 비중은?**
크게 봐요. SVG로 조각이 채워지는 인터랙션이 '모금이 아니라 놀이'의 핵심이라서요. 대신 저사양 폰에서도 가벼워야 하고 대기/확정 두 상태를 표현해야 해요.

**실시간 업데이트?**
네, 누가 보태거나 확인되는 순간 보고 있는 사람 모두에게 반영돼야 해요. WebSocket이냐 SSE냐는 같이 정해요.

**OG 최적화가 왜 중요해요?**
유입이 거의 다 단톡방·스토리 링크라서요. 미리보기에 진행률 카드가 떠야 클릭이 나요. 펀딩마다 바뀌는 동적 OG 이미지랑 카톡 미리보기 캐시 문제를 같이 다뤄요.

**비회원 메시지 수정·중복 참여는?**
간단한 비밀번호로 수정 권한을 줘요. 동일인 식별은 완벽할 수 없어서 어디까지 막을지 백엔드랑 정해요.

## 5. 백엔드
**결제 없으면 할 일 적지 않아요?**
많아요. 상품 링크 파싱, 공유 카드·OG 이미지 자동 생성, 참여 상태 관리, 알림 API 연동. 여기에 결제 시스템을 테스트 모드로 끝까지 만들어요.

**결제 트랙에서 뭘 만들어요?**
목표 채웠을 때만 결제되는 예약 결제, 웹훅 처리, 미달성 시 부분 취소·환불, 중복 결제 방지, 참여 상태(대기→확정→취소) 관리요. 결제사 테스트 모드는 가입만 하면 계약 없이 써요. 계약되면 스위치 하나로 켜요.

**여러 명이 동시에 보태면?**
그게 이 서비스의 기술 챌린지예요. 동시 참여 처리와 실시간 진행률을 직접 설계해요.

**상품 링크 파싱 범위는?**
쿠팡 우선, 나머지는 OG 태그로 최대한 읽고, 실패하면 직접 입력. 지원 범위 우선순위는 같이 정해요.

**가격 변동·품절은?**
목표 금액은 등록 시점 가격으로 고정해요. 내리면 남은 돈은 축하금, 오르면 추가 모금이나 대체 상품, 품절이면 대체 상품 추천이에요.

**데이터 모델은?**
참여 건마다 대기→확정 상태를 갖고 게이지는 확정 합계만 반영해요. 나중 결제를 대비해 입금 상태와 펀딩 상태를 처음부터 분리해요.

**운영자가 입금 확인해요?**
아니요, 운영자는 개설자 계좌를 못 봐요. 확인은 받는 사람이 '받았어요'로 해요.

**보안·개인정보는?**
계좌번호 대신 송금 링크, 펀딩은 기본 '링크 소지자만', 비회원 비밀번호는 해시 저장, 메시지는 금칙어 필터. 실결제 붙이면 별도로 설계해요.

**알림톡 시점?**
참여 발생(확인 요청), 목표 달성, 기한 임박, 생일 D-30. 비용 드는 채널이라 MVP 범위는 같이 정해요.

**인프라 비용?**
서버·이미지 생성·크롤링 정도. 초기엔 무료·저가 티어 + 이미지 캐싱으로 시작해요.

**기술 스택은?**
아직 안 정했어요. 팀 꾸려지면 같이 정해요.

## 6. 막히는 질문 공식
"아직 미정이에요 → 언제 정할 예정이에요 → 그 부분을 같이 정하고 싶어요."
- 법적 문제: 돈 보관 안 함 + 링크 소지자만 참여가 방어선, 법률 자문 1회 예정
- 서비스명: '보탬e'(행안부) 등 충돌, 상표 검색 후 확정
- 국내 근거: 해외(Throne·GiftCrowd·Kudoboard)로 컨셉 검증, 국내는 설문·인터뷰로 확인 중
- 제휴 수익 누수: 어디서 사든 자유라 누수 있음, 인증 보상으로 유도하고 기대치는 낮게
