# 가설-검증 계획서 — 보탬

> 원칙: 가장 위험한(틀리면 사업이 무너지는) 가설부터 검증한다. 코드 작성 전에 검증할 수 있는 방법을 우선한다.

## 리스크 맵

| ID | 가설 | 리스크 | 검증 방법 | 상태 |
|---|---|---|---|---|
| H1 | 받는 사람이 갖고 싶은 상품을 공개적으로 등록할 것이다 | 🔴 최상 | 인터뷰 + 컨시어지 MVP | ⬜ 미검증 |
| H2 | 보내는 사람이 계좌이체 대신 이 서비스를 쓸 것이다 | 🔴 상 | 컨시어지 MVP 참여율 측정 | ⬜ 미검증 |
| H3 | 목표 미달성 시에도 만족스러운 경험을 설계할 수 있다 | 🟠 상 | 컨시어지 MVP + 정책 테스트 | ⬜ 미검증 |
| H4 | 자금 보관 없이(규제 회피 구조로) 서비스가 성립한다 | 🟠 상 | 법률 검토 + 구조 설계 | ⬜ 미검증 |
| H5 | 참여자가 이후 개설자로 전환된다 (바이럴 루프) | 🟡 중 | MVP 이후 측정 | ⬜ 미검증 |

## H1. 위시 공개 가설 (문화적 리스크)

**가설**: 20~30대는 "나 이거 사줘"를 명시하는 체면 부담보다, 원하는 선물을 받는 효용을 더 크게 느낀다.

- **검증**: 인터뷰 10명([04-인터뷰.md](04-인터뷰.md)) + 실제 생일 앞둔 지인 5명에게 위시 등록 요청
- **성공 기준**: 요청받은 5명 중 3명 이상이 실제로 상품을 등록
- **실패 시 피벗**: 개설 주체를 받는 사람 → 친구(주최자)로 전환. "생일인 친구를 위해 내가 펀딩을 열어주는" 구조

## H2. 전환 가설 (행동 변화 리스크)

**가설**: 카톡 송금(3초)보다 번거롭더라도, 참여 현황 가시화·정산 제거·메시지 경험 때문에 보탬 링크로 참여한다.

- **검증**: 컨시어지 MVP — 링크 받은 사람 중 실제 참여 비율 측정
- **성공 기준**: 링크 수신자의 50% 이상 참여, 참여 과정 이탈률 30% 미만
- **핵심 조건**: 참여자는 **회원가입·앱 설치 없이** 참여 가능해야 함 (이 조건이 깨지면 H2는 거의 확실히 실패)

## H3. 미달성 경험 가설 (제품 설계 리스크)

**가설**: 미달성 시 "모인 금액만큼 기프트카드/포인트 수령" 정책이면 개설자·참여자 모두 만족한다.

- **검증**: 컨시어지 MVP에서 의도적으로 목표 대비 다양한 달성률 케이스 관찰 + 사후 인터뷰
- **대안 정책 후보**: ① 전액 환불 ② 모인 만큼 수령 ③ 개설자가 차액 부담 ④ 기한 연장 — [정책 결정서 D-1](05-정책결정서.md)

## H4. 규제 가설 (사업 구조 리스크)

**가설**: 초기에는 자금을 플랫폼이 보관하지 않는 구조(예: PG 에스크로, 달성 시점 일괄 결제, 기프티콘 발행)로 전자금융업 등록 없이 운영 가능하다.

- **검증**: 전자금융거래법·선불전자지급수단 요건 법률 자문 1회
- **주의**: 이 결과가 사업 구조 자체를 바꿀 수 있으므로 **MVP 개발 착수 전에 완료**

## 컨시어지 MVP 운영 계획

앱 없이 수동으로 공동선물 3~5건을 실제 운영한다.

- **도구**: 카카오톡 + 구글폼(참여 접수) + 노션 페이지(진행률 공개) + 운영자 계좌
- **대상**: 2~4주 내 생일/기념일이 있는 지인 그룹
- **측정**: H1(등록 수락률), H2(참여율·이탈), H3(미달성 케이스 반응)
- **기간**: 2~3주
- **산출물**: 검증 결과를 이 문서에 기록하고, [Lean Canvas](02-린캔버스.md)와 [MVP 요구사항](07-MVP요구사항.md)에 반영
