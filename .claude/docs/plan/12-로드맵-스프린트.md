# 로드맵 & 스프린트 계획 — 보탬

> 고정 조건: **개발 기간 2026-10-24(토) ~ 11-26(목), 약 5주.**
> PM 목표: **팀빌딩 완료 시점(10/24)에 와이어프레임·정책·검증 데이터가 완성된 패키지로 존재할 것.**

## 전체 구조

```
Phase 0  (7/15 ~ 10/23)   PM 단독 사전 작업 — 검증·정책 확정·와이어프레임
Phase 1  (10/24 ~ 11/20)  개발 스프린트 4회 (1주 단위)
Phase 2  (11/21 ~ 11/26)  버퍼·폴리싱·런칭 준비
```

원칙: 개발 5주는 늘릴 수 없으므로, **모든 '결정'과 '검증'은 Phase 0에서 끝낸다.** 개발 기간에 정책 논쟁이 생기면 그건 Phase 0의 실패다.

## Phase 0 — 팀빌딩 전 PM 사전 작업 (⚠️ 2026-09-09 기준 압축본)

**현재 9/9, 개발 시작까지 6주.** 원래 3개월로 잡았던 사전 작업을 6주로 압축해야 하므로, 아래는 "무엇을 자를지"까지 정한 현실판이다.

| 기간 | 필수 작업 | 완료 기준 | 압축 방식 |
|---|---|---|---|
| 9월 2주 | **정책 3개 확정**: D-1(미달성 → '모인 만큼 전달' 리프레임), D-5(금액 공개 범위), P2(진행률 표현 방식) | 와프를 그릴 수 있는 상태 | 못 자름 — **크리티컬 패스** |
| 9월 3주 | 압축 검증: 인터뷰 5명 + 모아줘·카카오 직접 사용 + 실제 생일 컨시어지 1~2건 | H1/H2 방향 판정 | 인터뷰 10→5명, 컨시어지 5→1~2건 |
| 9월 4주 ~ 10월 2주 | **와이어프레임** — 3층 구조 기준 핵심 루프 전 화면(테스트 결과·프로필·펀딩·참여·마감) | 클릭 프로토타입 | 화면 수를 Must 루프로만 제한 |
| 10월 2주 | 사용성 테스트 3명 → 와프 수정 | 이탈 지점 기록 | 5명 → 3명 |
| 10월 3주 | 킥오프 패키지 조립 + 사업자등록·쿠팡 파트너스 가입 | 와프 + 정책 + 검증 데이터 + 요구사항 확정본 | 법률 자문은 A 단계 진입 전으로 연기 가능 |

> **크리티컬 패스는 디자인이 아니라 결정이다.** 9월 2주에 정책 3개를 못 끝내면 와프가 밀리고, 와프가 밀리면 10/24 킥오프가 빈손이 된다.

## Phase 1 — 개발 스프린트 (10/24 ~ 11/20, 1주 스프린트 × 4)

킥오프(10/24 주말): 팀에 패키지 공유, 기술 스택·역할 확정, 스프린트 보드 세팅.

| 스프린트 | 기간 | 목표 (완료 = 데모 가능) | 비고 |
|---|---|---|---|
| S1 | 10/26(월)~10/30(금) | 프로젝트 셋업, 디자인 시스템, **펀딩 개설 플로우** (상품 링크 파싱, 페이지 생성, 공유 링크+OG) | OG 미리보기가 바이럴의 첫인상 — S1에 포함 |
| S2 | 11/2~11/6 | **참여 플로우** (비회원 열람, 금액 조각+메시지, 송금 딥링크, 참여 인증) | P2 완화안 구현. 여기가 제품의 심장 |
| S3 | 11/9~11/13 | **마감/전달 플로우** (D-day 처리, 메시지 모아보기, 인증 이미지 생성, 알림) + 어필리에이트 링크 변환 | 알림은 카카오 알림톡 대신 문자/이메일로 시작 가능 |
| S4 | 11/16~11/20 | **통합 QA + 실사용 베타**: 팀 지인의 실제 생일 2~3건으로 전 루프 실행 | 베타에서 나온 치명 버그만 수정, 신규 기능 동결 |

## Phase 2 — 버퍼 & 런칭 준비 (11/21 ~ 11/26)

- 베타 피드백 반영, 폴리싱(애니메이션·문구), 사기 방어 최소 장치(신고 버튼·비공개 기본값)
- 런칭 채널 준비: 인스타 스토리 템플릿, 첫 시드 유저(생일 임박 지인) 리스트
- 발표/데모 자료 (프로그램 종료일 11/26 산출물)

## 운영 프로세스

- **리듬**: 월요일 스프린트 플래닝(1h) / 매일 15분 스탠드업(비동기 가능) / 금요일 데모+회고(1h). 문서는 이 저장소에 커밋으로 남긴다.
- **스코프 원칙**: [07-MVP요구사항](07-MVP요구사항.md)의 Must만 S1~S3에 배치. Should는 S4 이후 여유 있을 때만. 일정이 밀리면 기능을 자르지 일정은 늘리지 않는다 (5주 고정).
- **PM의 스프린트 중 역할**: 스펙 질문 당일 응답(개발 블로킹 방지), 베타 유저 리크루팅, 런칭 준비 — 개발 기간에 새 정책 논쟁을 열지 않는 것이 최대 기여.
- **중간 체크포인트(11/6, S2 종료)**: 참여 플로우가 3탭 이내로 도는지 — 안 되면 S3 범위를 잘라서라도 참여 마찰 제거에 재투자.
