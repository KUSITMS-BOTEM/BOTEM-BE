## D-2. 상품 구매 구조 🟡 (2026-07-15 시나리오 정리)

3개 시나리오로 압축됨 (구조 논의 기록):

| 시나리오 | 구조 | 돈 흐름 | 규제/운영 무게 | 수익 |
|---|---|---|---|---|
| **B. 어필리에이트** (라이트) | 모인 돈은 개설자 계좌로(송금 링크), 구매는 개설자가 쿠팡 파트너스 링크로 | 플랫폼 무수납 | 최소 | 구매액 ~3% (30만 원 상품 ≈ 9천 원/펀딩) |
| **A. 기프티콘 한정 대리구매** | 참여자가 '선물 조각'을 PG로 결제 → 달성 시 기프티쇼 비즈 API로 기프티콘 즉시 발송 | PG 수납 (통신판매 구조) | 중간 — 통신판매업 신고 + PG 계약. 배송·품절·주소 문제 없음 | 상품권 마진 + 수수료 |
| **A′. 실물 대리구매** (쿠팡 등) | 모금 후 플랫폼이 실물 구매·배송 | PG 수납 + 구매대행 | 최대 — 가격 변동·품절·반품·주소 수집. 프레제뉴가 죽은 무게 | 수수료 |

- **잠정 결정**: B로 시작 → 루프 검증 후 A(기프티콘 한정) 추가. **A′(실물 대행)는 하지 않는다.**
- A의 규제 논점: 참여자가 '재화(기프티콘) 구매'를 하는 통신판매 구조로 짜면 자금 보관(전금법)이 아닌 일반 이커머스가 됨 — 미달성 시 PG 부분취소로 환불. ⬜ 법률 자문으로 확정 필요 (D-3와 연결)
- 카카오 선물하기 상품의 재판매·연동은 불가(입점 계약 필요) → 동일 카탈로그(스타벅스·치킨 등)를 기프티쇼 비즈로 커버

## D-3. 자금 처리 / 규제 ⬜ 🔴 최우선

| 질문 | 확인할 것 | 결정 |
|---|---|---|
| 참여금을 플랫폼이 보관하는가 | 보관 시 전자금융거래법상 선불전자지급수단 발행업/전자금융업 등록 대상 여부 | ⬜ 법률 자문 필요 |
| 우회 구조 성립 여부 | PG 에스크로, 달성 시점 일괄 승인(사전 카드 가승인), 기프티콘 즉시 발행 구조 각각의 적법성 | ⬜ |
| 환불 의무 | 미달성 환불 시 PG 수수료 부담 주체 | ⬜ |

**⚠️ 이 항목은 사업 구조 자체를 결정하므로 MVP 개발 착수 전에 법률 자문 1회 완료할 것.**

## D-4. 수익 모델 🟡 (D-2 시나리오와 연동)

원칙: **"유저는 돈을 내지 않는다"를 기본으로, 수익은 플랫폼(커머스)에서 받는다.**

| 후보 | 방식 | 판정 |
|---|---|---|
| 커머스 제휴 수수료 | 쿠팡 파트너스 등에서 구매액의 ~3% 수취 | ✅ 1차 수익원 (D-2 시나리오 B) |
| 상품권 마진 | 기프티쇼 비즈 단가와 액면가 차익 | ✅ 2차 수익원 (D-2 시나리오 A) |
| 목표가에 수수료 포함 (gross-up) | 30만 원 상품 → 목표 30.9만 원. N명이 나눠 내면 1인당 부담 미미 | ✅ **확정 (2026-07-15)**: A 단계의 가격 정책으로 채택. 부담 주체는 **참여자**(목표가에 포함), **"수수료 포함" 투명 고지 필수** — 펀딩 페이지에 상품가/수수료 내역 표시. 숨긴 수수료는 바이럴 서비스에 치명적 신뢰 리스크 |
| 펀딩 수수료 (노출형) | 참여 금액에서 명시적 차감 | ❌ "친구 선물에서 떼 가는" 인식 — 기각 |
| 프리미엄 기능 | 테마·카드 등 | 보류 (루프 검증 후) |

## D-6. 네이밍 / 상표 🟡 (2026-07-15 충돌 조사 반영)

- 잠정: 서비스명 **보탬**, 영문 **Botem** — 단, 아래 충돌 발견으로 재검토 필요
- **발견된 충돌** (상세: [경쟁분석](08-경쟁분석.md)):
  - '보탬e' = 행안부 지방보조금관리시스템 공식 명칭 → '보탬' 검색 점유 어려움
  - 'Botem' = 대전 소재 센서 기업 존재 (업종 상이)
  - 'botim' = UAE 메신저 앱, 철자 유사
- 대응 후보: ① 복합 네이밍 ② '보템' 재고(고유성 ↑) ③ 유지 + 영문 Botem으로 검색 통일
- ⬜ KIPRIS 상표 검색 (보탬 / 보템 / Botem, 35류·36류·42류) — 검색 결과로 최종 결정
- ⬜ 도메인·앱스토어 명칭 확보 확인
